# Código de conduta

Quem participa do Rizoma — issues, pull requests, revisão e discussão — segue este combinado. Ele adapta o [Contributor Covenant 2.1](https://www.contributor-covenant.org/version/2/1/code_of_conduct/). O mesmo texto está em [docs/contribuindo/codigo-de-conduta.md](docs/contribuindo/codigo-de-conduta.md).

## O que esperamos

- Gentileza com quem está chegando. Pergunta básica tem resposta direta, sem ironia.
- Crítica ao código e à ideia, não à pessoa. Na revisão, diga o que bloqueia o merge e o que é sugestão.
- Discordar com argumento. "Não" sem explicação não ajuda; explicar o receio ajuda.
- Aceitar que o projeto tem decisões já tomadas (fechado por padrão, uma empresa por instalação, regras no `core`). Mudar uma delas começa por uma conversa, não por um pull request surpresa.
- Respeito à privacidade. Não publique segredo, token, `.env` ou dado de cliente de quem usa o hub, nem em issue de exemplo.

## O que não cabe

Assédio, insulto, ataque pessoal, conteúdo sexual sem consentimento, e divulgação de informação privada de outra pessoa. Isso vale no GitHub e em qualquer canal em que você represente o projeto.

## Como avisar

Não responda no fio público se o relato expõe alguém. Escreva para quem mantém o repositório pelo canal privado do GitHub:

[github.com/wendersonbelko/rizoma/security/advisories/new](https://github.com/wendersonbelko/rizoma/security/advisories/new)

Use esse caminho também para conduta, enquanto o repositório não publicar um e-mail próprio. Diga o que aconteceu, onde (link da issue ou do PR) e quem mais viu. Quem mantém o projeto lê o relato, reserva o direito de remover comentário, fechar thread e, em caso repetido, limitar a participação.

Vulnerabilidade no software segue [SECURITY.md](SECURITY.md), pelo mesmo formulário privado, para não misturar com issue aberta.

## Escopo

Este combinado cobre os espaços do projeto. Conduta fora deles só entra na conversa quando alguém é prejudicado por se identificar como participante do Rizoma.
